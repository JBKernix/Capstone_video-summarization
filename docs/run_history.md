# 실행 이력과 성능 지표

앱 상단 메뉴의 **실행 이력**(React, 주소 `/history`)에서 확인합니다. 예비 Streamlit 화면에서는 홈의 **실행 이력과 성능 지표 보기** 또는 사이드바의 `run history`입니다.
앱과 CLI 모두 새 실행마다 이력이 자동 생성됩니다. 기존 요약 결과 저장 기능과 독립적이므로
별도 저장 버튼을 누르지 않아도 로그와 지표는 남습니다.
React 화면에서는 결과 파일이 아직 남아 있는(보존 기간 안의) 실행에 **결과 → 보기** 링크와
실행 상세의 **결과 화면 보기** 버튼이 표시됩니다.

## 저장 항목

기본 위치는 `runs/history/<실행 ID>/`입니다. CLI에서 `--run-dir`을 바꾸면 그 폴더 아래
`history/`에 저장되며, `--history-dir`로 별도 위치를 지정할 수도 있습니다.
앱(React·Streamlit)은 프로젝트의 기본 `runs/history/`를 조회합니다. CLI 이력을 앱에서 보려면
`--history-dir runs/history`를 지정하세요.

| 파일 | 내용 |
| --- | --- |
| `metrics.json` | 실행 상태, 전체/단계별 시간, 서버 모델 로딩 시간·횟수, 영상 정보, 설정, 프레임/STT/OCR/VLM 처리량, 오류 |
| `pipeline.log` | 파이프라인 표준 출력·오류와 traceback |
| `process.log` | 앱으로 실행한 경우 프로세스 시작 시점부터의 출력·오류 |
| `frame_metadata.json` | 추출 프레임 시각·경로 목록의 스냅샷(해당 단계 완료 시) |
| `stt_summary_result.json` | 음성 요약과 중요 시간대(해당 단계 완료 시) |
| `final_summary_result.json` | 최종 요약(완료 시) |

메타데이터 스냅샷에는 이미지 경로만 보관합니다. 원본 영상·JPG 자체는 이력에 복제하지
않으므로 다음 실행 후 그 경로의 이미지가 바뀔 수 있습니다. 이미지 보존은 기존의
**영상과 요약 결과 저장** 기능을 이용하세요.

지표는 단계 시작/종료 및 OCR 프레임·VLM 배치 처리 시 원자적으로 갱신됩니다.
성공·실패·키보드 중단 및 앱의 분석 중지 상태가 기록됩니다. 전원 차단이나 외부에서
강제 종료하면 마지막 `running` 상태가 남을 수 있으며, 자동 복구를 보장하지 않습니다.
앱이 자식 프로세스의 비정상 종료를 확인하면 `interrupted`로 기록합니다.

시간은 단조 시계로 초 단위 소수점까지 측정하며, 날짜는 UTC 오프셋과 함께 저장하고
화면에는 한국 시간으로 표시합니다. 전체 시간에는 준비·영상 변환·지표 저장도 포함됩니다.
LLM/VLM 시간은 통신과 큐 대기를 포함하므로 서버의 순수 추론 시간과 다릅니다.
GPU/CPU 사용률과 로컬 서버 토큰 사용량은 현재 수집하지 않습니다. Claude API 응답의 토큰 사용량은 별도로 저장합니다.

## 서버 모델 로딩 시간

앱과 `gpu-server` 수정본을 모두 적용하고 서버를 재시작하면 이후 실행부터 수집됩니다.
앱의 **실행 이력 → 실행 상세 → 단계별 시간 → 서버 모델 로딩**에서 확인합니다.

- 서버의 `load()` 호출을 측정합니다. 토크나이저/프로세서 준비, 모델 파일 로딩, GPU 전송 완료까지 포함합니다.
- LLM/VLM별 시간과 합계, 로딩 성공·실패 횟수, 이미 로딩된 모델 재사용 횟수를 구분합니다.
- 모델 재사용은 실제 로딩이 없으므로 0초입니다. 로딩 도중 실패한 시도의 시간도 합계에 포함합니다.
- 여러 VLM 배치가 각각 모델을 로딩하면 모두 합산합니다. 동일 작업을 반복 조회할 때는 중복 합산하지 않습니다.
- 단계별 시간에 이미 포함된 값입니다. 전체 시간에 로딩 합계를 다시 더하지 마세요.
- Whisper/OCR 모델 로딩, 모델 해제, 실제 생성 연산, 네트워크 및 큐 대기는 이 별도 로딩 지표에 포함하지 않습니다.

`metrics.json`의 `model_loading.jobs`에는 작업 ID·파이프라인 단계별 로딩 이벤트가,
`model_loading.summary`에는 집계가 저장됩니다. 서버 `logs/server.log` 및 클라이언트
`pipeline.log`(앱 실행은 `process.log`에도)에 로딩 시간 로그가 남습니다.
CSV에는 다음 열이 추가됩니다.

| CSV 열 | 의미 |
| --- | --- |
| `model_load_seconds` | LLM + VLM 로딩 시간 합계(실패 시도 포함) |
| `llm_load_seconds` / `vlm_load_seconds` | 모델 종류별 로딩 시간 |
| `model_load_count` | 로딩 성공 횟수 |
| `model_load_failed_count` | 로딩 실패 횟수 |
| `model_reuse_count` | 이미 로딩된 모델 재사용 횟수 |

이전 실행·구버전 서버·Claude API 모드의 로컬 LLM/VLM 로딩 지표는 빈 값으로 둡니다.
API 모드의 원격 Claude 로딩 시간을 측정하는 기능은 아닙니다. 진행 중이거나 연결이 끊긴
작업은 마지막으로 수신한 이벤트까지만 저장되므로 실제 전체 로딩 시간보다 작을 수 있습니다.
로딩 중 프로세스가 강제 종료되면 완료되지 않은 로딩 시도는 수집되지 않을 수 있습니다.

생략되거나 아직 계측되지 않은 개수는 0이 아닌 빈 값으로 표시합니다.
VLM 개수는 서버가 반환한 결과 수, 배치 수는 성공한 요청 수입니다.
OCR 일부 실패·VLM 후속 배치 실패 시 완료된 개수는 유지됩니다.

## 조회와 다운로드

- 영상명, 실행 상태, 요약 옵션으로 필터링합니다.
- 실행을 선택하면 단계별 시간 차트/표, 처리량, 설정, 원본 로그를 확인할 수 있습니다.
- **실행 목록 CSV 다운로드**는 현재 필터의 실행들을 합쳐 생성합니다(UTF-8 BOM, Excel 호환).
  공유 CSV 파일에 동시에 쓰지 않도록 각 실행 JSON을 원본으로 사용합니다.
- 상세 JSON과 전체 로그도 다운로드할 수 있습니다. 화면 로그는 마지막 100KB만 표시합니다.
- 과거 로그를 덮어쓰지 않습니다. 저장 공간 확보가 필요하면 앱을 멈춘 뒤 불필요한
  실행 폴더를 별도로 백업·정리하세요.

## 화면 확인용 예시

실제 성능 측정 없이 화면만 확인하려면 명시적으로 실행합니다.

```bash
python scripts/demo_run_history.py --write-demo-data
start_all.bat
```

브라우저에서 `http://127.0.0.1:8501/history`를 엽니다(Streamlit 화면은 `streamlit run app/main.py`).

예시 기록에는 `demo: true`와 화면 안내가 표시됩니다. 실제 벤치마크에 포함하지 마세요.
위 예시 생성 명령은 실행할 때마다 새 예시 기록을 만듭니다.

## 검증

```bash
python -m pip install pytest
python -m pytest -q
```

Whisper·OCR·외부 요약 서버 추론은 테스트 대역으로 검증합니다.
